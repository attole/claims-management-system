# API layer

The API's controllers, error body, identity, correlation, Idempotency-Key filter, uploads and downloads; it fills the current user from the token and supplies the correlation id the Application expects (`docs/layers/application.md` 'Provides and expects'). `.claude/CLAUDE.md` points here; read this file before changing or reviewing API code. Each rule is enforced as listed under Tests below.

## Layout

- The project root has four things: `Controllers/` (the endpoints and their `Requests/`, one record per query string or body, mapping itself to its query or command; responses are the Application's DTOs), `Errors/` (`ErrorBody`, the concurrency exception handler and `AddErrors`: the wire contract of failures), `DevAuth/` (the dev token feature, dev-only and removable as one unit) and `Pipeline/` (everything that runs around the actions: `Correlation/`, `Cors/`, `Health/`, `Idempotency/`, `Identity/`, `Jwt/`, `Swagger/`). What controllers or other layers need goes at the root; what only runs around the actions goes under `Pipeline/`. There is no catch-all `Configuration/` folder; a feature folder holds its options, its `<Feature>ServiceExtensions` and any middleware or filter.
- Namespaces follow the folders (`ClaimsModule.API.Pipeline.Identity`, `ClaimsModule.API.DevAuth.Configuration`) and the test project mirrors them. No folder is named `Options`, because the namespace would shadow `Options.Create`.
- `Pipeline/ApiPipelineServiceExtensions` composes the features: `AddApiPipeline` calls each feature's `Add...` (the `Pipeline/` features, `Errors/`, `DevAuth/`) and `UseApiPipeline` each `Use...` in the one order that matters (see Identity and correlation, below), so `Program.cs` has two API calls besides the layers' own. A new feature adds its line there and keeps its own extension class.

## Controllers and routes

- An action maps the request to one command or query, sends it through MediatR and returns the mapped `Result`. It holds no business logic and builds no error JSON.
- Routes are plural kebab-case nouns under `/api`, except the specification's own names (`/status`, `/reference/...`); the route test allows exactly the routes listed here. The reserve decision routes are the specification's, which name a history row. Three assessment routes are not built: a reserve update, a combined decision route and a policy coverage route (the policy search result carries the coverage types).
- Routes exist only for the three screens, the specification's route table and the set-up of a draft. The other Application commands (severity, limit override, remove a document) have no route.
- The routes are the specification's table (`S:API-*`) under `/api/claims`, `/api/reference` and `/api/policies`, plus routes that serve a screen element or the set-up of a draft: the notes update, the retry of a failed GL posting, the closure pre-check, and the routes that let a Draft reach Open (assign the handler, link a policy, update the loss, acknowledge and waive an issue, add, update and remove a risk object). A claim is created with its creator as handler, so the handler route only changes the handler. The full list with paths is under Wire format, below.

## Closure pre-check

- `GET /api/claims/{id}/status-check?targetStatus=Closed` shows what blocks a transition before the click (S:UI-Detail-Header, S:BR-ST-03); it works for any target status.
- `CheckClaimStatusQuery(ClaimId, TargetStatus)` loads the claim and runs the same transition as `ChangeClaimStatusCommand` through a runner map the two handlers share, under the request's user and role, and never commits, so nothing is saved or dispatched.
- It returns the failing findings (code, severity, message, field). The frontend shows them, blocks confirm while a Critical finding remains, and asks for the reason, note or liability confirmation when a finding names `Reason`, `Note` or `IsLiabilityConfirmed`. The result is advisory: `PUT /api/claims/{id}/status` runs the rules again and its 422 is authoritative.
- It is a read, so the Idempotency-Key filter does not apply.

## Errors

- One error mapper turns a `Result` into the response: validation 422, not found 404, forbidden 403, conflict 409. An unknown id is always a 404, including an id of another claim or a child (a party, a reserve row) the claim does not own.
- A `ConcurrencyConflictException` (a concurrent edit or a duplicate key) is returned by `ConcurrencyConflictExceptionHandler` as a 409 with the same body; the exception text is never on the wire.
- The body follows the specification's sample (S:API-ErrorShape): `type`, `title`, `status` and `errors` grouped by field. `type` is the short name of the error kind, not a URI: `ValidationError`, `NotFoundError`, `ForbiddenError` or `ConflictError`. `title` is readable text. An error without a field goes under `General`. The error code is not on the wire.
- A request that cannot be bound at all (a missing non-nullable value included) is rejected with the same 422 body, not a 400.
- A successful write returns `CommandResponse<TData>` (`{ data, warnings }`, nested in `ApiControllerBase` so a derived controller names it directly in its attributes), a warning being the Application's `Warning` (`code`, `message`, `field`); no warnings is an empty list, so the frontend reads one shape. A read returns its data directly, a page as the Application's `PagedResult`.
- Controllers derive from `ApiControllerBase`: `QueryAsync(request, ct)` returns a query's data, `CommandAsync(request, ct)` the envelope, and a failed `Result` becomes the error body in both. `ErrorBody` owns the body: `From(errors)`, `Create(kind, message)`, `Unauthorized()`, `FromModelState(...)`, `ToResult()`, `WriteAsync(context, cancellationToken)`. `ErrorsServiceExtensions.AddErrors` replaces the framework's model-state response with the 422 body through `PostConfigure` (a `Configure` would be overwritten by `AddControllers`), registers `ConcurrencyConflictExceptionHandler` as an `IExceptionHandler` (run by `UseExceptionHandler()`), and adds the error responses (401, 403, 404, 409, 422 with `ErrorBody`) to every action's OpenAPI entry.
- The success status is declared, not passed: a write action carries `[ProducesResponseType<CommandResponse<TDto>>(StatusCodes.Status201Created)]` (or 200), a read action `[ProducesResponseType<TDto>(...)]`. `CommandAsync` reads the one declared 2xx status from the action metadata, defaults to 200 when none is declared and throws when two are, so the status and the OpenAPI document share one source.
- 401 and 403 use the same body: the JWT challenge writes `UnauthorizedError` (with `WWW-Authenticate: Bearer`), its forbidden event `ForbiddenError`, and the current-user middleware and the dev token endpoint use the same writer. A missing or wrong `Content-Type` is the framework's own 415, outside this contract.

## Identity and correlation

- The actor and role come from the authenticated user, never from the request. The token's role becomes a `UserRole` through `UserRole.From`, accepting only an exact role name (`RoleNames.IsKnown`): a number, a comma list, other casing or padding is refused, in the token and in the dev user settings.
- Authentication is a bearer token (S:API-Auth) with claims `sub` (user id), `org` (organisation id), `role` (`Handler`, `Supervisor` or `Manager`) and `name` (header display). Inbound claim mapping is off, so the middleware reads the names as written.
- Persistence builds `ClaimsDbContext` and its interceptors from the scoped `ICurrentUser` and `IClock`, so the API registers `ICorrelationContext`, and a middleware right after authentication sets `ScopedCurrentUser` (id, organisation and role from the token) before any handler runs. The user's organisation is the tenant filter value; dev users carry the seeded organisation id, without which the seeded policies and cause-of-loss codes are invisible (`docs/layers/persistence.md` 'Migrations and seed data').
- **Dev token** (the specification's mock authentication): `DevTokenIssuer` and `DevAuthController` (`POST /api/dev/token`) in `DevAuth/` (controller, issuer and extensions at its root, `Configuration/` for the options and their validator, `DevTokenRequest` and `DevTokenDto` beside the controller), behind `DevAuth:Enabled`; no Application port or Infrastructure service. The users and the seeded organisation id are settings, validated at startup while the switch is on, with the token lifetime capped at 1440 minutes. The request is `{ userId }`, the response the token, its expiry and the user. With the switch off it answers 404, and an unknown user answers 404. There is no access code or other gate: the specification asks for a mock sign-in with hardcoded users, so anyone who can reach the route can get a token for a configured user, which is acceptable only on fake data. The README and Swagger document it as a simulation.
- Anonymous routes are only the dev token endpoint, Swagger, the signed local download route and the two health endpoints.
- **Health** (`Pipeline/Health/`): `GET /health/live` answers 200 while the process runs; `GET /health/ready` answers 200 when `DatabaseHealthCheck` reaches the database, else 503. Both return a plain status word, never details. They are mapped endpoints, not controller actions, so `HealthServiceExtensionsTests` proves they need no token. The hosting health probe and the deploy smoke test use `/health/ready`.
- Role checks are Domain rules (`HasApprovalAuthority`, `HasRejectionAuthority`, `IsNotSelfApproval`, the reopen transition) (S:ROLE-Enforcement), so a role failure is the 422 of its finding with the specification's message. No action uses `[Authorize(Roles = ...)]`; the API requires an authenticated user and nothing more.
- **Correlation** (S:AUD-Correlation): a scoped `CorrelationContext` holds a new GUID per request (a job scope gets its own), read by every audit entry of the request, and a middleware at the start of the pipeline returns it in the `X-Correlation-Id` response header when the response starts, error responses included. An incoming `X-Correlation-Id` is ignored, because it is untrusted input and the audit column is a GUID.
- The Hangfire dashboard cannot use the bearer token (a browser page cannot send the header), so it stays behind its switch (default off), is open to every request when on, and may be on only where the data is fake (the demo has it on). The fallback policy covers every request after authorization, so the dashboard and Swagger come before `UseAuthentication` and the OpenAPI document is mapped with `AllowAnonymous()`. The order in `ApiPipelineServiceExtensions.UseApiPipeline`: correlation, exception handler, HTTPS redirection, CORS, dashboard, Swagger, authentication, current user, authorization, health, controllers.

## Idempotency-Key

A write with an `Idempotency-Key` header is idempotent (S:API-IdempotencyKey); the header is optional and applies to every write action, uploads included. It is a global resource filter, not a MediatR behavior, because only the API knows the header, route, final status and body, and a resource filter runs before model binding, where the raw body can still be read. An action's request size and form limit attributes are authorization-stage filters, so their limits are raised before this filter reads the form.

1. A key longer than 200 characters (the column length) is rejected with the 422 body.
2. Before the action the filter hashes the body and calls `IIdempotencyStore.BeginAsync` with the key, method, route (the request path) and hash; user, organisation, method and route are part of the store's key. A JSON body is hashed as is; a form or multipart body by its fields and files (name, file name and bytes), because the multipart boundary is random per request. A file up to 50 MB is one extra sequential read through request buffering.
3. `Started`: run the action. `Completed`: return the stored response. `InProgress`: 409. `BodyMismatch`: 422.
4. After the action the filter calls `CompleteAsync` with the status and body, only for a 2xx. A refusal or error is not stored (the staged key row is never saved), so the same key sent again runs against the current state.

A key saved with no response means the request is still running or crashed after its commit: it answers 409 until the key expires. A request without the header runs normally and is not stored. A replay returns the first successful response even if the claim has changed; fresh state comes from a read. A key expires after 24 hours and then counts as new (store and cleanup: `docs/layers/persistence.md` 'Readers and repositories', `docs/layers/infrastructure.md` 'Jobs').

## Wire format

- JSON is camelCase. Closed sets (statuses, roles, components) and enums travel as their names in both directions (a `JsonStringEnumConverter` on the controllers); an unknown name is a 422. Dates and times are ISO 8601, money is a number.
- Lists are paged with `page` and `pageSize` (default 1 and 25, `PagingDefaults`; a size above 100 answers 422) and return `PagedResult` (`items`, `page`, `pageSize`, `totalCount`, `totalPages`).
- Claims list filters bind from the query string with the specification's names (`status`, `dateFrom`, `dateTo`, `assignedHandlerId`, `causeOfLossCode`, `policyId`, `search`); `status` repeats for a multi-select (`status=Open&status=Draft`) and maps to the Application's `Statuses`.
- Claim routes under `/api/claims`: `POST /` (201, the draft with its children in one call), `GET /{claimId}`, `PUT /{claimId}/status`, `GET /{claimId}/status-check?targetStatus=`, `PUT /{claimId}/notes`, `PUT /{claimId}/handler` (`{ handlerId }`), `PUT /{claimId}/policy` (`{ policyId }`), `PUT /{claimId}/loss` (`LossRequest`), `GET /{claimId}/audit`, `POST /{claimId}/parties` (201), `DELETE /{claimId}/parties/{partyId}`, `POST /{claimId}/risk-objects` (201, `RiskObjectRequest`), `PUT /{claimId}/risk-objects/{riskObjectId}` (`RiskObjectRequest`), `DELETE /{claimId}/risk-objects/{riskObjectId}`, `POST /{claimId}/issues/{issueId}/acknowledge` and `POST /{claimId}/issues/{issueId}/waive` (supervisor or manager, a Domain rule).
- Reserve routes under `/api/claims/{claimId}/reserves`: `GET /` (summary and history), `POST /` (201, `ReserveRequest`), `POST /{reserveHistoryId}/approve`, `POST /{reserveHistoryId}/reject` (`{ rejectionReason }`), `POST /{reserveHistoryId}/retract` and `POST /{reserveHistoryId}/retry-posting`.
- Document routes under `/api/claims/{claimId}/documents`: `GET /` (links) and `POST /` (201, multipart with `file`, `documentType` and `notes`), plus the anonymous `GET /api/documents/download?token=` (see Documents, below). A file whose first bytes do not match its declared type answers 422 with `DOC_CONTENT_MISMATCH`.
- Reads: `GET /api/claims`, `GET /api/policies/search?q=`, `GET /api/reference/cause-of-loss-codes` (optional `perilCategory`), `GET /api/reference/claim-statuses` (each status with its allowed next statuses).
- A body or query string binds to a record in `Controllers/Requests/` that maps itself to its command or query (`ToCommand`); an Application request record with its own validator (the party, loss, risk object and reserve bodies) is used as the body as it is.

## Documents

- The upload is multipart (S:API-POST-claims-documents). Size, type and content are Domain rules (S:DOC-MaxSize, S:DOC-MimeAllowlist, `DOC_CONTENT_MISMATCH`), so the user gets their 422 message. The Application reads the first 512 bytes of the file and the Domain rule `IsContentMatchingType` checks them against the declared type; `DocumentContentTypes` is the one table of allowed types and their signatures (`docs/layers/domain.md` 'Domain modeling').
- The server must not reject first: Kestrel's default body limit is about 28.6 MB, so the upload action raises its request size and form limits to 51 MB (the Domain limit plus multipart overhead), and a larger body fails the form read with a request-body-too-large message, answered as a 422 in the usual body.
- The document list returns a download URL per file (S:API-GET-claims-documents). For Azure it points at the blob. For the local provider the API serves the signed route and streams what `ILocalDocumentDownloads.Open(token)` returns; the Infrastructure implementation validates `LocalDownloadToken`, checks the provider is the local file system, finds the file and names it, and under Azure returns nothing, so the route answers 404. The file name is the original name behind the upload id, the content type comes from its extension (octet-stream when unknown), and no database row is read, so the tenant filter is not involved. An invalid, tampered or expired token answers 404, a missing `token` 422. The token is the only check, which is why the route is anonymous. Static files are not used.

## Swagger

- Swagger (`Swagger:Enabled`, default off, on in development) shows a bearer authorize button and a note that the dev token is a simulation.
- The OpenAPI document describes enums by name: the string enum converter is registered for the MVC options and for the HTTP JSON options the document generator reads. The frontend generates its types from it (`docs/layers/frontend.md` 'API types').

## Tests

A rule above without a test is a rule to add one for.

- A route test checks every route is kebab-case plural (S:DATA-Naming), with the listed exceptions as an explicit allow-list.
- Three route-driven tests walk every route from the action descriptors: every route without a token answers 401, and every claim read route answers 404 for an unknown claim and for a claim of another organisation, so a new route is covered without a new test. Write routes keep their own tenant and validation tests, because they need a valid body.
- Two journey tests drive the main flow through the real pipeline: an open claim, a reserve submitted and approved by two users, the move to pending payment, then the detail and the audit; and a claim created through `POST /api/claims` with a policy and an initial reserve, then opened, with its audit trail read back, proving a Draft reaches Open through the API alone.
- A reflection test checks that no action uses `[Authorize(Roles = ...)]`, every action is authenticated except the anonymous routes, every write action is covered by the Idempotency-Key filter, and every action of an `ApiControllerBase` controller declares exactly one 2xx `[ProducesResponseType]` (a write with `CommandResponse<>`).
- The error mapper has a test per error kind (status and `type`), for the `General` key and for the concurrency exception handler.
- The Idempotency-Key filter has a test per outcome (`Started`, `Completed`, `InProgress`, `BodyMismatch`), one for a key over 200 characters, one for a multipart upload and one that a refused request is not stored (a test endpoint, and a real status change refused and repeated with the same key after the fix).
- The correlation middleware has a test that it ignores an incoming header, returns a new GUID in `X-Correlation-Id` and exposes the same value through `ICorrelationContext`.
- The pre-check has handler tests for a pending reserve, an unresolved Critical issue and an open balance, and every handler test checks that `CommitAsync` is never called.
- The dev token endpoint has tests for a configured user (the token is accepted by the API), an unknown user (404), the switch off (404) and a bad dev user stopping the host at startup.
- The upload has a test that a body just under 50 MB reaches the Domain and one that a larger body is refused by the server; both run on a real Kestrel host (`KestrelApiFactory`).
- The API tests run on `WebApplicationFactory` against LocalDB (or `CLAIMS_TEST_SQLSERVER`) and skip when no server answers, failing instead when `CLAIMS_TEST_SQLSERVER` is set. One shared fixture migrates the database once, and each test creates its own organisation (`CreateOrganisationAsync`, with one active cause code), so the tenant filter isolates the tests. Reserve tests need a policy, so they use the seeded organisation and `SeedOpenClaimAsync` (an open claim with a linked policy and a unique claim number).
- The test host removes every hosted service, which stops the Hangfire server, while options validation still runs. It replaces `IPostingScheduler` with a recording fake and `IRecurringJobManager` with a mock, so a test proves which jobs are enqueued and never runs one; the real Hangfire path is in `docs/layers/infrastructure.md` 'Tests'.
