General working plan: how AI is used across the project, which skill or rule applies where, and what gets recorded. The assessment suggests five phases; this plan keeps them and adds the Claude Code setup of this repo. Referenced from CLAUDE.md. Recruitment and grading context is in notes-recruitment-context.local.md (local-only).

PHASES

Phase 0 - Setup (done)
- Task suggestion: prepare tools and context before designing anything.
- Here: CLAUDE.md (rules), skills (design, explore, code-review, dev-log, spec-check, ai-journal), the rule register (docs/rules.local.md), settings.json (permissions), local markdown copies of the domain documents, these temp notes.
- Exit: user has reviewed CLAUDE.md and skills; settings.json in place. Done; CLAUDE.md has since been restructured (Domain section, Tests, Naming) and check_workflow.py also verifies the code layout.

Phase 1 - Domain and architecture
- Task suggestion: load the requirements as context, have AI help shape the project structure and domain model (aggregate roots, value objects, events), then validate its assumptions against the requirements.
- Here: the user leads the domain first (entities, lifecycle, rules). The design skill produces the architecture design and flags out-of-order requests. Assumptions Claude makes are surfaced as [?] blocks, never silently settled. Output: original architecture plan written into docs/ARCHITECTURE.md (the final artifact, updated as decisions change).
- Record: design-<topic>.md with DECISIONS; AI mistakes and corrections noted for the AI report.
- Exit: domain model and project layout agreed; ARCHITECTURE.md first version.

Phase 2 - Data model
- Task suggestion: give AI the entity descriptions and conventions, generate EF configurations and migrations, then verify conventions.
- Here: CLAUDE.md 'Data & naming conventions' is the checklist. Design skill covers the schema before application code. Migrations are generated by tooling, never hand-edited.
- Record: review pass with code-review against the conventions.
- Exit: migrations apply from scratch on a fresh database; seed data present.

Phase 3 - Backend (current: Domain packs 1 to 3 done; next the lifecycle pack, then reserves, reference data and audit, then Application and Persistence)
- Task suggestion: scaffold commands, queries and validators; give each handler its business-rule context; use AI on idempotency and concurrency questions.
- Here: pack by pack, in the dependency order of the design's build sequence, with boilerplate batched inside a pack; stop after each pack for review. Rules are cited by source-qualified ID (see CLAUDE.md 'Domain sources'). dev-log for tracing flows such as the background jobs. code-review (fresh Opus reader) after each pack.
- Record: corrections found by code-review or by the user; prompts worth showing.
- Exit: all endpoints and jobs implemented; business rules covered by validators or domain logic and tests.

Phase 4 - Frontend
- Task suggestion: AI scaffolds components, forms and the service layer; the multi-step form logic is validated by hand.
- Here: design skill for the screen and state design; explore to check backend contract before building services; code-review contract check when both sides change.
- Exit: the three screens work against the backend; errors surface to the user; no HTTP outside the service layer.

Phase 5 - Review, deployment, documentation
- Task suggestion: review all AI output against the business rules, document corrections, use AI to draft the documents.
- Here: full code-review on the branch; CI/CD pipeline and Azure deployment (outward actions are always confirmed first); README, ARCHITECTURE.md final pass, AI-WORKFLOW.md written from the recorded prompts and corrections; export of the conversation history.
- Exit: deployed and working end to end; deliverables complete.

Loop inside every phase
- design (user approves) -> implement one pack -> user reviews and asks for explanations -> optional dev-log tracing -> code-review + passive spec-check -> user builds, tests, commits -> update the temp note -> record any AI correction.
