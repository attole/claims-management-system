Persistence-layer notes moved out of design-domain-model.md. The Persistence project holds only the options and registration skeleton today; read this note when its packs begin. Most findings come from a throwaway EF Core 9.0.20 spike (SQL Server provider for the model and script, SQLite in memory for round trips); the spike is outside the repo.

OPEN

- The SLA job's 24-hour dedupe needs the latest breach entry per claim; it reads the audit log by claim and event type, which needs an index there (S:JOB-SLA-Dedupe).
- Indexes on columns inside a complex type (for example on party role or email) were not checked; verify before relying on one.
- The other nullable columns need the same check as the loss date and the estimated amount before they are mapped.

PROVISIONAL

- Claim number generation is an Application interface implemented in Persistence by a counter row per organisation and year, incremented with UPDATE ... OUTPUT inside the claim's transaction (S:CLAIMNO-Atomic), so there are no gaps; the Domain record only validates the format (S:BR-C-04). The format holds seven sequence digits, so the counter refuses past 9,999,999 per organisation and year with a conflict before ClaimNumber.Create would throw.
- Draft-tolerant schema: the nullable loss date and the cause code without a foreign key are described in docs/ARCHITECTURE.md 'Schema departures from the spec'; this note covers the mapping only.
- Closed sets: Persistence holds the EF converters (marker text out, record in), built with the Application closed-set service that the DbContext receives by constructor. No design-time factory is planned; add a small one only if migrations cannot create the context. Plain enums use EF's built-in text conversion.
- Details values: ClaimLossEvent holds LossDetails, ClaimParty holds PartyDetails and ClaimRiskObject holds RiskObjectDetails. Each is mapped as a complex property into the entity table and replaced as a whole (a spike confirmed that only the changed members are marked modified; two entities sharing one details instance saved without error). The default column names carry a Details_ prefix; give every member HasColumnName to match the spec table, and HasPrecision(19, 4) on the amount.
- Every entity has a private parameterless constructor with empty placeholders, because EF cannot bind domain constructors that take values it does not map (Claim, its five children, Reserve and ReserveChange); `EntityConstructionTests` builds each through it.
- Nullable columns on non-nullable struct properties are refused by EF, so absent values are sealed record classes with an Empty instance: LossDate and EstimatedLossAmount (and ClaimNumber and LossDetails for placeholders). The converter maps NULL to Empty and Empty to NULL (ConvertsNulls) and the property is declared optional; the spike confirmed a nullable datetimeoffset column and a Draft round trip for the loss date.
- Estimated loss amount: the spec column is nullable, so no estimate is not an estimate of 0 (user decision). Map it as a converted scalar on a nullable decimal(19,4) column, NULL <-> Empty, and check that a stored zero reads back as a set estimate. This part was not spiked.
- Closed sets inside the details (party role and type, named PartyClaimantRole, PartyPersonType and so on) are converted scalars (text with a maximum length); the spike used a plain switch in place of the registry.
- Audit columns (user decision 2026-10-16, replaces the earlier split): CreatedAt, UpdatedAt, UserCreated and UserModified are EF shadow properties, not Domain properties. The save interceptor stamps them: Added sets CreatedAt and UserCreated, Modified sets UpdatedAt and UserModified, with the time and user from the Application's request clock and current user (the same source the input builders stamp from, so audit times equal the business times on entities). The Domain sets only business fields: OrganisationId on the base Entity (ITenantOwned) and, for a removed risk object, the soft-delete flag and DeletedAt (ISoftDeletable); a removed party is deactivated instead.
    - Root touch: when a child of an aggregate is added, modified or soft-deleted, the interceptor also marks the aggregate root modified (children hold their root id, ClaimId), so the root's UpdatedAt moves and its RowVer changes. This is what serializes concurrent changes to one claim's children, and the SLA job (S:JOB-SLA, claims in Draft or Open with UpdatedAt older than 48 hours) depends on it. The Domain no longer has a Touch.
    - The interceptor needs the current user and the time from Application interfaces (not the Domain). The names are used as strings, so a test against a real context must cover every interface member.
    - Soft delete: the global query filter reads the flag through the interface property; a hard Remove on a tracked entity should be turned into the soft-delete flag by the interceptor only for entities that do not do it themselves.
    - OrganisationId lives on the base Entity, which implements ITenantOwned; soft delete stays per entity with ISoftDeletable. Read models and the SLA job read the shadow columns with EF.Property.
- Queries: computed members (IsSet, IsClaimant), the marker of a converted closed set and range comparisons on converted values do not translate to SQL. Equality against an instance and OrderBy do translate. List and search queries therefore do not use the Domain entities: they project to DTOs, or use flat read models mapped to the same table with plain nullable columns (for example a nullable date column for loss date ranges), and filter on plain columns. Never filter a Domain entity with AsEnumerable; that loads rows into memory. Domain rules run on a loaded aggregate and are unaffected.
- ClaimValidationIssue is a child collection of the claim with the Finding complex property (a Finding: code, field, message, evidence and the FindingSeverity enum as a scalar; evidence holds the checked values the issue was raised on, up to the trimmed loss description, so it needs a text column of matching size), the state closed set as a converted scalar, a resolved time and a resolved-by id with empty defaults; it has the private parameterless constructor and the audit, delete and tenant fields like the other children. Cleared issues stay as history; the query for open issues filters on the state.
- Reserve change: the details hold the component type (copied from the reserve at submit) and the change keeps SubmittedAt, both mapped columns; a unique index on (ReserveId, ChangeSequence) backs the positive-sequence guard in the Domain and the idempotency key.
- Concurrency: configure the RowVer token on the claim, the reserve and the reserve change; a child change and every reserve change touch the claim row (the root touch above).
